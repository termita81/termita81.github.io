description: Run a structured discovery interview before building a new web app
argument-hint: [one-line pitch of your app idea, optional]
---

I want to build a web app. Before writing or planning any code, interview me
to gather everything you need. Ask about one topic at a time (or a small
related group of questions), wait for my answer, and adapt follow-up
questions based on what I say — don't dump the whole list below on me at
once. Use your judgment on which topics are relevant; skip ones that
obviously don't apply and tell me you're skipping them.

My initial idea (if given): $ARGUMENTS

Cover these areas:

1. **Problem & users** — What problem does this solve, and for whom? Is this
   for me, a specific audience, or the public? What's the core "job to be
   done"?

2. **Core use cases & MVP scope** — Walk through the main things a user does
   in the app. Separate must-have (MVP) features from nice-to-have/later
   features. What's explicitly out of scope for v1?

3. **Tech stack & hosting** — Any required or preferred language/framework?
   Any existing repo/codebase this should live in or integrate with? Where
   will it be hosted/deployed (existing infra, a platform I already use, or
   no preference — recommend one)? Any constraints (must be static, must
   avoid a backend, must run offline, etc.)?

4. **Design & branding** — Is there an existing look/brand to match (a site,
   style guide, color palette, logo)? Any reference apps/sites whose UI I
   like? Rough layout expectations (single page, multi-page, dashboard,
   mobile-first, etc.)?

5. **Data & backend** — What data does the app need to store? Does it need
   user accounts/auth (and if so, what kind — email/password, OAuth,
   passwordless)? Any third-party APIs or services to integrate (payments,
   email, maps, AI, analytics, etc.)? Any data privacy/compliance concerns?

6. **Non-functional requirements** — Expected scale (personal project vs many
   users)? Performance expectations? Accessibility requirements? Target
   browsers/devices (mobile, desktop, both)? Offline support needed? SEO
   relevant, or is this behind a login?

7. **Reuse & existing assets** — Is there existing code, a design system, a
   component library, or another project I want you to reuse or reference
   rather than build from scratch?

8. **Timeline & effort** — Is this a quick prototype, a weekend project, or
   something meant to be maintained long-term? Any deadline?

9. **Success criteria** — How will I know this is done and working? What
   does "shipped" look like — a live URL, a passing demo, something else?

Once you have enough to proceed, summarize what you've gathered into a short
spec (problem, users, MVP feature list, stack/hosting decision, key
constraints) and confirm it with me before you start planning the
implementation or writing any code.
